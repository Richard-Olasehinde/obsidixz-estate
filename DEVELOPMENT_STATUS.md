### Files created

| File | Purpose |
| --- | --- |

| `src/app/api/enquiry/route.ts` | POST handler: validate → reject bots → rate limit → sanitise → deliver |
| `src/components/forms/EnquiryForm.tsx` | Client form: validation, states, duplicate protection, accessibility |
| `src/components/forms/fields.tsx` | Labelled field primitives with error wiring |
| `src/app/contact/page.tsx` | Hosts the form and reports live delivery availability |

### Behaviour

- **Mandatory fields:** full name, business email, enquiry type, requirements/message, privacy
  acknowledgement. **Optional:** company, target US location.
- **Client and server validation** from one shared module. The server never trusts the client.
- **States:** idle → validating → submitting → success / field errors / delivery failure /
  not configured. The button is disabled in flight.
- **No false success.** Success is shown only for a 2xx from the destination. An unconfigured
  deployment returns 503 and the form says so, keeping the visitor's text.
- **Spam:** honeypot, submit-timing threshold, per-IP rate limit, length and newline limits.
- **Sanitisation:** control and zero-width characters stripped, whitespace collapsed, spreadsheet
  formula prefixes neutralised.
- **Accessibility:** every field labelled, `aria-invalid` and `aria-describedby` on error, errors
  announced in a live region, focus moved to the first invalid field.

## Stage 5 — Responsive implementation

### Method

No browser engine is available in this environment, so responsive correctness was established
by **measurement rather than by eye**: `scripts/check-layout-metrics.mjs` reads the real
Montserrat and Open Sans advance widths (the same files the site serves, cut to static
instances in `scripts/fonts/`) and proves that the widest word in every multi-column cell fits
the narrowest column that breakpoint produces. This is the defect class that actually causes
horizontal scrolling on a site like this — a single long word forcing a grid wider than its
container.

### Defects found and corrected

| Where | Defect (measured) | Correction |
| --- | --- | --- |
| `ProcessSteps` (used on Home, How It Works, Services) | At 1024 px the 5-column grid gives a 192 px cell → 144 px content box. "requirements" in Montserrat 600 at 23.2 px needs **163 px** → overflow pushing the last two steps outside the container. | `sm:grid-cols-2 xl:grid-cols-5`. At 1024 the grid is 2-up (432 px cells). |
| `services/page.tsx` process strip | Same 5-column defect at 1024 px. | `sm:grid-cols-2 xl:grid-cols-5`. |
| `contact/page.tsx` next-steps | 3 columns from 640 px → 186 px cells, too tight for the body copy at that width. | 3 columns from `md` (768 px). |
| All multi-column grids | Not previously measured. | Now covered by 26 assertions at 360 / 390 / 640 / 768 / 1024 / 1280 / 1440 px. |

### Verified safe

| Element | Worst case | Result |
| --- | --- | --- |
| Hero headline "Smarter Research." | 315 px at 360 px (320 px available) | Fits — 15 px headroom |
| Hero headline at 1440 px | 550 px in a 696 px column at 60 px type | Fits |
| Header logo + 6 nav items + CTA | 1049 px of 1216 px at every width ≥1280 | Fits |
| Buttons at 360 px | "Discuss Your Requirements" 267 px of 320 px | Fits |
| Longest body words | "acknowledgement" 151 px of 320 px | Fits |
| Legal page headings at 360 px | Longest single word "jurisdiction" 128 px | Fits, wraps naturally |

### Responsive behaviour by width

| Width | Layout |
| --- | --- |
| 360–389 px | Single column throughout. Header collapses to logo + menu button. Hero panel stacks under the headline. Buttons full width. Form single column. |
| 390–639 px | Same as 360, more breathing room. Hero type scales with `clamp()`, unchanged layout. |
| 640–767 px | Process steps 2-up. Service scope 2-up. Not-for list 2-up. Header still collapsed. Footer becomes 3-column at `lg`. |
| 768–1023 px | 3-up card rows begin. Contact sidebar still stacks below the form. |
| 1024–1279 px | Sidebar layouts engage (`lg`). Process steps remain 2-up. **Desktop nav still collapsed** — deliberate, because six nav items plus the CTA need ~810 px of a 960 px content width. |
| 1280–1439 px | Full desktop navigation. Five-across process steps. Hero becomes two-column. |
| 1440 px+ | Content caps at 1216 px (`max-w-[76rem]`); type caps at its clamp ceiling. |

### Navigation and touch

- Mobile panel is a disclosure below the header with `aria-expanded` / `aria-controls`, closes on
  link click and on `Escape`, and locks body scroll while open.
- All interactive targets are at least 44 px tall (menu button 44×44, buttons `py-3`/`py-3.5`,
  inputs `py-2.5` plus label).
- Form controls are full width on mobile; the message field is `resize-y` so it cannot be
  dragged wider than the viewport.

### Overflow protection

`body { overflow-x: hidden }` is set as a final guard, but the underlying causes were fixed
rather than masked: no fixed pixel width over 360 px exists in any component, all grids are
either single-column or measured to fit, and no text uses `whitespace-nowrap`.

## Post-Stage-8: static export and the custom-domain build

Preparing the GitHub Pages deployment exposed three defects in the deployment path. All three
produced a page that **returns HTTP 200**, which is why none would have been caught by a status
check.

| # | Defect | Consequence had it shipped |
| --- | --- | --- |
| 1 | `next build` output (`.next/`) was uploaded as the Pages artifact | `index.html` sits in `.next/server/app/`, not the artifact root — **every URL 404s** |
| 2 | The workflow set `NEXT_PUBLIC_BASE_PATH=/<repo>` | Correct for `github.io/<repo>/`, **wrong for a custom domain**, which serves at `/` — every asset 404s on the live domain |
| 3 | No `CNAME` in the artifact | The custom domain does not bind to the deployment |

### Fixes

- `NEXT_OUTPUT_EXPORT=1` switches `next.config.ts` to `output: 'export'`, emitting `out/` with
  `index.html` at the root. `trailingSlash` gives directory-style URLs; `images.unoptimized` is
  required because an export cannot re-encode on demand.
- `manifest.ts`, `robots.ts` and `sitemap.ts` gained `export const dynamic = 'force-static'`,
  without which the export refuses to build.
- The base path is **unset**, and the workflow now fails if a repository prefix reappears in the
  output.
- `CNAME` and `.nojekyll` are written into `out/` before upload.

**Trade-off, recorded deliberately:** the bare `github.io/<repo>/` URL is not a usable preview for
this build. The custom domain is, once the certificate issues.

### Tooling fixed at the same time

| Tool | Defect |
| --- | --- |
| `check-accessibility.mjs` | Hardcoded `http://localhost:3000` and ignored `SITE_ORIGIN`, so it silently tested the wrong build — or crashed — whenever the site ran anywhere else |
| `smoke-test.mjs` | Treated a trailing-slash redirect as a failure, so it could only ever pass against a Next server. Also asserted status `404` for a removed endpoint and server-set response headers, neither of which a static host provides |

The header checks are now **reported as host-provided rather than asserted**, because GitHub Pages
cannot set response headers at all. The absence is real and worth seeing every run.

## Post-Stage-8: Node 22.23.4 Undici smoke-test crash fixed

The Actions log from the failed run narrowed the issue to `npm run smoke`, after the export had built
and the static server had started. The stack ended in Node's `undici` HTTP parser:

- Status-only checks now use `HEAD` for internal links, local assets, the Open Graph image and
  response headers.
- The slash-redirect helper consumes the redirect body before following the new URL.
